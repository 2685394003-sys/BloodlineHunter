## ⚠️ 重要坑:Edit/Write 工具会破坏含中文文件的编码

- **现象**:对本项目的 `.cs`(含中文注释)用 Edit 工具改,或 Write 工具整体覆盖后,文件被以 **GBK/系统默认编码** 写盘,原 UTF-8 中文注释(包括**未改动过的**行)变成乱码(`鐗规晥` 那种 UTF-8-as-GBK 表现),`python utf-8` 解码报错。
- **修复办法**:用 Python 以 `encoding='utf-8'` 通过 **bash heredoc** 直接写盘(`open(path,'w',encoding='utf-8',newline='\n').write(content)`),内容在 heredoc 里保持 UTF-8。写完后务必用 `python open(...,encoding='utf-8')` 校验一次。
- **教训**:以后改任何含中文(或非 ASCII)的文件,优先用 Python heredoc 写 UTF-8,或改完立即用 Python 校验编码;不要信任 Edit/Write 工具对中文的编码处理。
- 本文件 `Assets/Scripts/Player/PlayerAttact.cs` 已用此法修复并校验通过(UTF-8 OK, 4027 chars, 花括号 14/14)。

- **办法**:拆成 ≤3KB 的多段 heredoc,首段 `open(...,'w')` 后续 `open(...,'a')` 追加,最后一段统一校验(UTF-8/BOM/花括号)。本次 MonsterSpawnPoint.cs 分 3 段写入成功
- 与既有"Edit/Write 工具破坏中文编码"坑并存:中文 .cs 文件 = Python heredoc 分段写 + 写后校验

## CS1501 编译错误修复(17:52)——Unity 6000.5 API 差异,长期记住

- **现象**:SpawnPointsAimBoss.cs(43,34) 报 `error CS1501: No overload for method 'FindFirstObjectByType' takes 2 arguments`
- **根因**:**Unity 6000.5.4f1 的泛型 `FindFirstObjectByType<T>` 没有 `(FindObjectsInactive, FindObjectsSortMode)` 双参重载**(只有无参形式)。我之前按印象写了双参调用,编译不过
- **修复**:改用全版本可靠的 `Resources.FindObjectsOfTypeAll<T>()` —— 能找到**禁用的场景物体**,但也会带出 prefab 资产,必须用 `cand.gameObject.scene.IsValid()` 过滤只保留场景物体。修复后 SpawnPointsAimBoss.cs 3690 字符,花括号 11/11,UTF-8 无 BOM
- **用户确认**:boss 是故意禁用的。现行为:AimBoss 锁定禁用 boss 的停驻位置照常转向;MonsterSpawnPoint 找不到激活 boss 就正常刷怪(设计行为)
- **教训**:在本项目(6000.5)写"查找含禁用物体"时,直接用 `Resources.FindObjectsOfTypeAll<T>()` + `scene.IsValid()` 过滤,不要试图用 FindObjectsInactive 双参重载
