## 重要发现(易踩坑)

1. **ImageGen 并行调用会冲突**:同一轮消息里发起多个 ImageGen DeferExecuteTool 调用,它们的 `output_dir` 会被覆盖(全部写到最后一个调用的目录),文件名时间戳也会重复,导致实际只产出 1~2 张图。**必须一张一张串行生成,每张生成后立即重命名为唯一文件名**(我用 `frame_NN.png` 编号)。
2. **AI 对"极弱起始弧光"表现不稳定**:用户在 Prompt 里写 "small, thin, low opacity" 想表达初始雏形,模型会退化成模糊光团,而不是锐利细弧。frame_01/02 因此不是清晰的弧形,只有到 frame_04 才开始有标准新月形。已在 README 里诚实告知。
3. **不依赖任何图像库就能拼帧**:`zipfile`(标准库)足够打包多帧交付。Pillow/ImageMagick 等只有在用户授权装的情况下再用。

## 攻击范围控制特效大小(继续 PlayerAttact.cs)

**需求**:用户在 StatsManager 里调大 `weaponRange` 时,要让 `gongjidian`(AttackPoint)上的特效弧光等比变大,判定框/伤害范围/特效三者用同一个 `weaponRange` 联动。

**落地**:在 `PlayerAttact.cs` 增加
- `[SerializeField] float vfxVisualRadiusAtScaleOne = 2f`(特效在 scale=1 时的可视半径,Inspector 校准常数);
- `SyncVfxScale()` 方法:`s = weaponRange / vfxVisualRadiusAtScaleOne; AttackPoint.localScale = (s,s,s)`;
- 在 `Update()` 里每帧调用 `SyncVfxScale()`,Play 模式下实时跟随。

**关键结构核查**:`gongjidian`(fileID 8060869640720166179)= AttackPoint,`localPosition {x:1.46}`,组件仅 Transform+Animator,**无 SpriteRenderer、Animator.m_Controller={fileID:0} 未挂控制器**。结论:缩放 `AttackPoint.localScale` 是安全的(Unity 的 localScale 不影响物体自身相对父级的位置,且它没有子物体),特效绕自身原点缩放不会偏移。**但当前特效尚不能渲染**——等用户把 SpriteRenderer+控制器(连好 24 帧)接通后,Play 模式才能看到缩放效果。

**限制**:缩放同步只写在 `Update()`(避免把场景标脏为"未保存");编辑器静止时不会自动缩放。若用户要编辑器实时预览,可加 `[ExecuteAlways]` 或把 `SyncVfxScale()` 放进 `OnDrawGizmos`(代价:场景持续变未保存)。

## ⚠️ 重要坑:Edit/Write 工具会破坏含中文文件的编码

- **现象**:对本项目的 `.cs`(含中文注释)用 Edit 工具改,或 Write 工具整体覆盖后,文件被以 **GBK/系统默认编码** 写盘,原 UTF-8 中文注释(包括**未改动过的**行)变成乱码(`鐗规晥` 那种 UTF-8-as-GBK 表现),`python utf-8` 解码报错。
- **修复办法**:用 Python 以 `encoding='utf-8'` 通过 **bash heredoc** 直接写盘(`open(path,'w',encoding='utf-8',newline='\n').write(content)`),内容在 heredoc 里保持 UTF-8。写完后务必用 `python open(...,encoding='utf-8')` 校验一次。
- **教训**:以后改任何含中文(或非 ASCII)的文件,优先用 Python heredoc 写 UTF-8,或改完立即用 Python 校验编码;不要信任 Edit/Write 工具对中文的编码处理。
- 本文件 `Assets/Scripts/Player/PlayerAttact.cs` 已用此法修复并校验通过(UTF-8 OK, 4027 chars, 花括号 14/14)。
